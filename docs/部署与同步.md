# 官网部署与版本同步

方案基于维护者确认：域名未备案、暂不开通收费资源、使用公开官网仓库。沿用现有 `catleaf-website` Pages 项目、域名和页面设计，不修改其他项目或 DNS。

## 免费下载中转

构建生成 `_worker.js` 与 `_routes.json`，仅 `/downloads/*` 调用 Function，其余页面保持静态服务。安装包不进入 `public/` 或 `dist/`，不受静态资源25MiB上限影响；请求体流式转发，支持 GET、HEAD 和单段 Range，禁止任意 URL 代理和访客凭据转发。未知文件返回404，网络或源文件长度错误返回502，不将错误页伪装为 APK。

这是境外网络中转，不是独立国内存储镜像。访问者无需直连 GitHub，但 Cloudflare 仍依赖 GitHub 下载源；GitHub 删除/替换资产、网络波动、免费额度耗尽都可能导致失败。下载后可用公布的 SHA-256 校验；中转流不在每次请求内重新计算完整文件哈希。资产禁止同code静默替换，必须以更高code修复。

账户当前为 Workers Free，每日100,000请求额度与该账户其他 Worker 共用；不自动升级套餐。未完成国内电信、联通、移动无代理实测，不承诺国内速度。GitHub备用入口保留。

参考：[Pages高级模式](https://developers.cloudflare.com/pages/functions/advanced-mode/)、[调用路由与免费额度](https://developers.cloudflare.com/pages/functions/routing/)、[Workers流式响应](https://developers.cloudflare.com/workers/runtime-apis/streams/)、[资源限制](https://developers.cloudflare.com/workers/platform/limits/)。

## 自动同步流程

官网仓库每30分钟检查 CatLeaf 的公开 Release，另提供手动运行。GitHub 定时任务可能延迟；不将源码push当APK发布，不使用排除预发布版的 latest Release API。不需要改动 Android 发布流水线，也无需跨仓库写入令牌。

1. 固定 App 主分支提交SHA读取该版本发布清单，核对对应 Release 非draft、published=true及资产摘要；版本标签中的清单可能仍是发布前状态。
2. 完整下载 APK 至被忽略的 `.release-work/`；验证大小、SHA-256、实际证书、包名、版本与minSdk。拒绝更低code、同code换包、非既有签名或超过100MiB预算的包。
3. 从同一已核验数据生成首页、下载页、官网JSON和下载白名单；保留旧版本映射。更新说明取自该版本清单，历史更新记录不自动改写。
4. 通过检查、测试和构建后部署公开预览，验证实际完整下载、Range、清单和页面。预览通过且主分支未变化才部署现有生产项目，最后再次验证官网并提交两份数据文件。
5. 没有新版本则不重复下载和部署；任务串行运行。晋升前失败不改变生产；晋升后网络验证失败会将任务标红，需按下方方式回滚，不宣称跨外部服务原子成功。

更新清单为 `https://catleaf.konoyuming.top/releases/latest.json`，UTF-8 JSON、64KiB以内、无需凭据。code24当前仍读取GitHub raw清单；交给App开发者在下一份同签名包中接入官网URL，需重新验证检查与覆盖升级。官网部署不能修改既有APK的端点。

## 启用所需配置

自动部署默认关闭，只有 `RELEASE_SYNC_ENABLED=true` 才运行。

在 GitHub 环境 `release-sync` 中配置：

- Secret：`CLOUDFLARE_API_TOKEN`，专用于部署的 Cloudflare token。只授予选定账户的 Cloudflare Pages Edit；不授予DNS、R2、D1或账户管理权限。该权限是账户级Pages写入，Cloudflare不能据此限制到单一Pages项目，需理解其范围后授权。
- Variable：`CLOUDFLARE_ACCOUNT_ID`，填既有官网所在账户ID。
- 仓库 Variable：`RELEASE_SYNC_ENABLED=true`，在凭据配置后开启。先手动运行一次；不能将被跳过的任务称作端到端通过。

不要将token发到聊天，不复制本机宽权限OAuth到CI，不把token保存进仓库。公开仓库的PR检查只有读取权限，不获得部署Secret；仅官网发布任务有本仓库数据写入权限。后续可以将环境设为人工审批，但那会停止无人值守自动部署，按维护者选择配置。

## 手动部署与回滚

```sh
npm ci
npm run check:release
npm run test:release
npm run build
npx wrangler pages deploy dist --project-name=catleaf-website --branch=release-check --commit-dirty=true
npm run verify:download -- https://实际预览地址
npx wrangler pages deploy dist --project-name=catleaf-website --branch=main --commit-dirty=true
npm run verify:download -- https://catleaf.konoyuming.top
```

使用代理的本地Node22.23.2环境，验证命令需 `node --use-env-proxy --experimental-strip-types tools/verify-download.mjs https://实际地址`；无代理超时不能写成国内网络验收通过。CI运行环境不依赖本机代理。

回滚前保存当前失败运行与部署ID；在 Pages 控制台将最后已验证生产部署 Rollback，核对下载、JSON与页面后，再将官网仓库的版本数据恢复至同一记录。旧安装包和映射不删除，不自动卸载或降级手机App；有缺陷的App应发布更高code修复。
